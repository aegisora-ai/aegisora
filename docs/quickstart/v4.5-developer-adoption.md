# Aegisora v4.5 — Developer Adoption Quickstart

Aegisora is an execution security layer, not an agent framework. Keep your existing model, orchestration, and tools. Wrap each consequential tool with the Aegisora SDK so the call crosses the runtime authorization boundary before the underlying handler runs.

## Install in a workspace

```bash
pnpm add @aegisora/sdk
```

For repository development, build first:

```bash
pnpm install --frozen-lockfile
pnpm build
```

## Register an agent and protect tools

```ts
import { AegisoraClient } from "@aegisora/sdk";

const aegisora = new AegisoraClient();

// Register the canonical agent identity in the local Aegisora runtime.
aegisora.agent({ name: "support-agent" });

const safeTools = aegisora.protectTools({
  agentId: "support-agent",
  contract: {
    contractId: "support-task-v1",
    agentId: "support-agent",
    allowedTools: ["crm.lookup", "crm.update"],
    approvalRequiredTools: ["crm.update"],
    maxExecutions: 20,
  },
  tools: [
    {
      name: "crm.lookup",
      description: "Read one customer record.",
      async execute(input) {
        // Call your existing CRM client here.
        return crm.lookup(input);
      },
    },
    {
      name: "crm.update",
      description: "Update one customer record.",
      async execute(input) {
        // This handler is not entered until Aegisora authorizes the call.
        return crm.update(input);
      },
    },
  ],
});

// Pass safeTools to your existing agent/framework in place of raw tools.
```

## Contract behavior in this first adoption slice

- Tool names are exact capabilities; wildcard permissions are not supported.
- A tool omitted from `allowedTools` cannot be registered in this protected set.
- `expiresAt` is an optional ISO date string.
- `maxExecutions` limits attempted calls across this protected set.
- `approvalRequiredTools` sends those calls through the runtime's ESCALATE path; this SDK slice does not itself implement the human approval UI.
- Each call uses the runtime's ToolRegistry authorization and execution boundary.
- Inputs are structured-cloned before authorization so caller-side mutation during asynchronous checks cannot silently change the executed object.

## Important integration boundary

`protectTools()` governs the tool handlers passed through these wrappers. It cannot protect a separate raw network client, shell command, database connection, or tool invocation that bypasses the wrappers. Route every consequential tool through the protected set, and test the complete workflow before production rollout.

The legacy `protect()` helper gates the top-level `agent.run()` invocation only. It does not automatically intercept tools called internally by that agent. Use `protectTools()` for per-tool enforcement.

## Validation

The SDK test suite covers allowed execution, unlisted tools, expiry, execution limits, approval escalation, input snapshotting, and the legacy top-level entry gate.

```bash
pnpm --filter @aegisora/sdk test
pnpm build
pnpm typecheck
pnpm test
```
