# Aegisora v5.0 - Agent Execution Control Plane

## Milestone

v4.0 established Execution Continuity with Continuity Seal.

v5.0 evolves the existing governance dashboard into an authoritative control plane for autonomous agent execution.

This is not a cosmetic dashboard release. The objective is to unify agent inventory, authority, policy, simulation, approvals, execution operations, evidence, incidents, and runtime response into one operational system.

## Product Thesis

Aegisora should answer:

- Which agents exist?
- What authority does each agent have?
- Which policies govern each execution?
- What is the agent attempting to execute?
- What risk and approval state applies?
- Is execution still continuous and valid?
- What actually happened?
- What evidence proves it?
- What should an operator do next?

## Global Architecture

The runtime data plane should own latency-sensitive execution enforcement.

## Security Invariants

- Runtime remains the final enforcement authority.
- BLOCK and ESCALATE never reach the protected upstream.
- Approval cannot bypass enforcement.
- Caller metadata cannot redefine canonical tenant, agent, capability, provider, or route identity.
- Control-plane outage cannot create a direct-execution bypass.
- Invalid policy state fails closed according to the deployment contract.
- Continuity Seal remains bound to the authorized execution.
- Material control-plane mutations are auditable.

## v5.0 Definition of Done

- [ ] One canonical control plane represents agents, authority, policy, decisions, executions, evidence, and incidents.
- [ ] Agent fleet can be discovered and governed from one operational surface.
- [ ] Effective authority and blast radius are visible.
- [ ] Policy supports simulate, review, deploy, monitor, and rollback.
- [ ] Simulation uses the same governance semantics as runtime.
- [ ] Approval always returns through runtime enforcement.
- [ ] Continuity Seal state is visible during execution operations.
- [ ] Evidence can be traced from event to execution to policy to authority.
- [ ] Incidents can trigger runtime containment.
- [ ] Control-plane failure cannot create a direct-execution bypass.
- [ ] Policy state is scoped, signed, versioned, expiring, and auditable.
- [ ] Multi-tenant boundaries remain enforced.
- [ ] Global deployment, recovery, and scale behavior are tested.

## What v5.0 Is Not

- Not a cosmetic dashboard redesign.
- Not disconnected admin pages.
- Not a generic AI observability console.
- Not a second competing policy engine.
- Not a control plane placed in the execution hot path.
- Not an operator bypass around runtime enforcement.
