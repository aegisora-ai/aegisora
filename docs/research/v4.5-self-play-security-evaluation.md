## Scope of this first implementation

This milestone implements a bounded, model-adapter-based `PROPOSE -> SOLVE -> VERIFY` evaluation loop for security-classification tasks. The first supported task kind is `DEDUCTION` only.

- The proposer returns a strict declarative task schema.
- The validator rejects unknown fields and executable payloads.
- The existing Aegisora `SecurityEngine` independently derives ground truth.
- The solver receives the validated task without ground-truth labels.
- The verifier compares a strict machine-readable answer with the oracle result.
- The output is an in-memory evaluation report with a binary verification reward.

## Explicit non-goals

This is AZR-inspired evaluation infrastructure, not a reproduction of the complete Absolute Zero Reasoner training system. It does not train or update model weights, implement reinforcement-learning optimization, or claim self-improvement. Abduction, induction, adaptive curriculum, persistent rollouts, and model training are future research milestones.

No model-proposed code, shell command, URL, tool call, or production agent action is executed. The proposer and solver adapters must honor the supplied `AbortSignal`; timeout handling cannot forcibly terminate an adapter that ignores cancellation. Production adapters should run behind an independently secured process/container boundary.

The engine is an evaluation component. It does not grant permissions and must not be wired as an authority source for `ALLOW`, `BLOCK`, or `ESCALATE` decisions.

## Security constraints

- Workspace-scoped task fingerprints and bounded in-memory deduplication.
- Exact object schemas; unknown keys are rejected.
- Input, identity, action, proposal-count, timeout, and cache bounds.
- Independent deterministic oracle; solver cannot supply expected labels.
- Strict answer schema and exact verifier comparison.
- Errors are returned as stable codes, without persisting raw provider error text.

## Next milestones

## Research reference

The Absolute Zero paper describes model-proposed tasks, solving, and programmatic verification, including deduction, abduction, and induction. This Aegisora implementation intentionally narrows the first production-oriented slice and does not reuse the research repository's executor.
